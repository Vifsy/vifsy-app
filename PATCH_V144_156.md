# PATCH V144.156 — Admin Command Center

## Syfte
Bygger om startsidan för Admin till ett nytt responsivt kontrollcenter utan att ersätta fungerande backendflöden. Workers, Smart Queue, publicering, Rescue Center, krediter, AI-generering och befintliga adminsidor ligger kvar.

## Ny adminöversikt
- Ny desktop/tablet/mobil-layout inspirerad av referensdesignen.
- Stor admin-hero med viktigaste KPI:erna.
- KPI för varumärken, genererade inlägg denna månad, genereringsframgång och ärenden som kräver åtgärd.
- Prioritetsrad för rescue/misslyckanden, väntande godkännanden och systemproblem.
- Snabbåtkomst grupperad i:
  - Kunder & innehåll
  - Kreativa bibliotek
  - Ekonomi & krediter
  - System & kvalitet
- Alla befintliga viktiga adminverktyg är fortfarande tillgängliga via länkar eller systemverktygssektionen.
- Översättningsunderhåll och OpenAI emergency stop är bevarade.

## Statistik
- 30-dagars diagram för genererade/publicerade inlägg.
- Fördelning av innehållsformat.
- Toppländer baserat på varumärkesprofiler.
- Senaste kreditjusteringar.

## Faktiska AI-kostnader
Bygger vidare på v144.155 cost metering.
- Visar endast kompletta USD-summor.
- Median per innehållstyp.
- Medelvärde per innehållstyp.
- P90 per innehållstyp.
- Antal kompletta körningar som underlag.
- Övergripande median och snitt för senaste 30 dagarna.

Median är huvudmåttet i UI eftersom ett fåtal dyra retries eller videojobb annars kan göra medelvärdet missvisande.

## Systemstatus
Ny live-monitor för:
- Vercel / cron-monitor
- Supabase Database
- Supabase Storage
- Smart Queue / worker lanes
- OpenAI
- Resend
- Stripe
- Meta Graph API
- Kling
- Shotstack

Kontrollerna använder read-only/reachability-anrop och skapar inga AI-generationer eller betalningar.

## Historik och uptime
- Ny health-cron var 5:e minut.
- Aktuell status sparas separat.
- Incidenthistorik sparas när en tjänst har två på varandra följande misslyckade/degraderade kontroller, för att inte registrera ett enstaka nätverksblipp som ett riktigt driftstopp.
- Incidenten stängs automatiskt när tjänsten återhämtar sig.
- Admin visar 30-dagars uptime per system och senaste incidenter.

## SQL
Kör `spreelo-v144.156-SQL.sql` en gång i Supabase SQL Editor.

Migreringen är additiv och skapar endast:
- `system_health_status`
- `system_health_incidents`

Båda är RLS-skyddade och endast service-role får läsa/skriva.

Om SQL ännu inte är körd fungerar live-status fortfarande, men historik/uptime kan inte sparas permanent.
