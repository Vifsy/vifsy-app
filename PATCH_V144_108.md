# Spreelo v144.108 — Fail Fast + Remote Rescue Images

Base: **v144.106 Admin Queue + Rescue ZIP**.

This release includes the unpublished v144.107 fail-fast changes as well as the v144.108 rescue-image update, so v144.107 does **not** need to be deployed separately.

## v144.107 included: fail fast on protected product sources

- Confirmed protected product access (for example 403 / Access Denied / known security challenge) is terminal for the occurrence.
- The old paid indexed/GPT research chain is skipped once Spreelo knows the protected source cannot be completed normally.
- The work item moves to **Misslyckat** with explicit rescue metadata instead of remaining in `retry_pending`.
- Fresh already-verified catalog/public-feed material can still complete the job without paid research when enough valid material already exists.

## v144.108: rescue ZIP can use remote original product images

The rescue package no longer has to contain binary product image files.

Each rescue product may provide either:

- `image_file` — an actual JPG/PNG/WEBP inside the ZIP, or
- `image_url` — a direct HTTPS URL to the verified original product image on the customer's site/CDN.

If both are present, `image_file` wins.

For an `image_url`, Spreelo now:

1. validates that the URL resolves to the public internet and uses HTTPS,
2. follows at most four validated redirects,
3. applies a 15 second timeout and 20 MB hard download limit,
4. validates the downloaded bytes with Sharp as JPEG/PNG/WEBP,
5. copies the image into the existing `admin-review-assets` Supabase Storage bucket,
6. uses the Spreelo Storage copy in preview and regeneration.

This means regeneration never depends on the external CDN after a successful rescue import.

## Rescue prompt updated

The Admin → Misslyckat → **Öppna uppdrag i ChatGPT** prompt now asks for manifest schema version 2.
A minimal valid rescue ZIP may contain only `manifest.json`, where each product has a verified direct `image_url`.

The prompt still permits packaged image files when ChatGPT can provide them.

## Security

Remote rescue-image downloads reject private/internal addresses through Spreelo's existing `assertPublicHttpUrl` guard, require HTTPS, validate every redirect, enforce size/time limits, and validate actual image bytes before storage.

## Database

**No new SQL migration is required.** v144.108 uses the v144.106 work-queue/rescue schema already installed.
