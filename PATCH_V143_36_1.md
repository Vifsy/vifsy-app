# Spreelo v143.36.1 — semantic calendar visual correction

## Deployment order

1. Run `supabase/v143_36_1_visual_semantic_reclassification.sql` once in Supabase SQL Editor.
2. Deploy this application package to Vercel.
3. Let `/api/cron/generate-calendar-visuals` run every five minutes.

## Repair behavior

- All existing non-generic images are classified once from their actual pixels.
- Campaign opportunities are classified independently from their own multilingual text.
- Campaigns and images meet only through canonical English `theme_key` and English `theme_tags`.
- Existing Storage filenames and URLs are unchanged.
- Two images and up to eight campaigns are classified per cron invocation.
- Every record has at most three attempts; completed records are never sent to OpenAI again.
- Up to twenty completed campaigns are reconciled to the best completed image per invocation.
- New image jobs wait while the legacy image repair is active instead of receiving a misleading generic image.

## Progress query

```sql
select *
from public.calendar_visual_reclassification_progress
order by record_type, status;
```

The repair is complete when both `assets` and `campaigns` only show `ready`. Rows marked `failed` have exhausted three attempts and should be inspected before cleanup.
