# Spreelo v144.102 — admin mass tests

Built directly on v144.101.

## What was added

### Admin → Masstest
A new admin-only mass-test workspace can run real Spreelo generation across several brands at once.

For each brand the admin can choose:
- connected social platforms
- AI Content Studio formats
- 1–5 repetitions per selected Studio format
- active calendar campaigns
- the whole campaign or individual campaign posts
- required test data for Custom post, Focus page, Offer/campaign and Giveaway formats

The summary shows the exact number of jobs before the test is started. A single batch is capped at 500 jobs as a guardrail.

### Runs through the normal production queue
Test jobs are normal one-off `automation_rules` with `next_run_at = now`, so they are ready immediately and are consumed by the existing shared queue and v144.101 worker-lane guard. There is no backdating workaround.

The normal generation pipeline is intentionally preserved:
- normal product discovery and verification
- normal campaign/product metadata
- normal OpenAI/image/video generation
- normal retries/failures
- normal worker fairness/locks
- normal generation-cost tracking
- normal product/content history
- normal admin review objects

### Customer credits are not deducted
`is_admin_test` is checked inside the normal worker. For test jobs only:
- no balance requirement is performed
- no customer credit balance is decremented
- no credit transaction is inserted
- no reserved automation credit is consumed

The rule keeps its normal content credit cost for context, while actual provider cost is still captured through the existing generation-cost ledger.

### Normal Godkänn workflow
Generated test posts are saved in the normal `posts` table and forced to `admin_review_status = pending`, so they appear in the ordinary Admin → Godkänn workflow. They get a small `TEST · MASSTEST` badge, can be filtered by test batch, and retain the normal actual-cost display.

Direct customer delivery before Spreelo admin review is explicitly disabled for test runs. If the admin later approves/releases a test post, the existing normal approval/release workflow is used.

### Test progress and actual cost
The mass-test page shows:
- waiting / running / completed / failed jobs
- brand, campaign, format and platform for every job
- real generation cost per completed post
- total real provider cost by currency
- recent batch history

### Failure diagnostics
Every failed test can produce a copyable diagnostic package containing available:
- brand and website
- batch/job/rule IDs
- campaign and format
- occurrence history
- exact failure stage/code/message
- automation run logs
- product URLs and selections from the run log
- runtime incident records
- retries and durations
- Vercel environment/deployment/commit identifiers when available
- persisted technical stack from runtime incidents when available

Secrets/tokens are redacted before diagnostic text is returned.

Buttons:
- `Kopiera fellogg` per failed job in Masstest
- `Kopiera komplett testlogg` from a failed test in Godkänn
- `Hämta diagnostik` for all failed jobs in a batch
- `Kör om fel` to clone only failed rules back into the same batch and queue them immediately

## Required SQL
Run before deploying v144.102:

`supabase/v144_102_admin_mass_tests.sql`

It adds:
- `admin_test_batches`
- test-context columns on automation rules, posts, occurrences, run logs and admin review cases
- test batch references for runtime incidents
- an occurrence trigger that copies test context from its automation rule

`admin_test_batches` has RLS enabled and no anon/authenticated access; the admin API uses the service role after normal Spreelo admin authentication.

## Important behavior
This is deliberately a real end-to-end generation test, not a simulation. Test runs can therefore update the same product/content usage history that normal generation updates. That is intentional so product variety and repeated-run behavior can be tested realistically. Customer credits are the exception and are bypassed.
