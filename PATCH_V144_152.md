# PATCH V144.152 — Logo source-of-truth + top-left Product Post logo + responsive Home content plans

## Scope
This patch intentionally changes three tightly defined areas:
1. customer logo state / lifecycle
2. Product Post logo placement + matching Brand Profile preview
3. Home → Innehållsplaner responsive layout

Carousel generation is not redesigned in this patch.

## 1. Brand Profile is the source of truth for logos
- Uploading a **first/new** customer logo now enables `logo_enabled_by_default` automatically.
- Replacing an existing logo preserves an intentionally disabled logo setting.
- Removing a logo continues to clear:
  - `logo_url`
  - `logo_storage_path`
  - `logo_enabled_by_default = false`
- Editorial Product Posts refresh logo settings directly from `brand_profiles` immediately before generation.
- The refresh is now **fail-closed**: if the current DB logo state cannot be read, Spreelo does not reuse a possibly stale cached logo for that run.
- No example logo or old storage asset is used as a fallback when the current brand profile has no active logo.

## 2. Product Post logo moved to top-left
- Editorial Product Post logo overlay moved from bottom-right to **top-left**.
- Logo width is restrained to roughly 13.5% of the post width, with a consistent safe margin.
- Bottom 9–10% remains pure breathing room whether a logo exists or not.
- GPT-Image prompt now keeps a small calm top-left area when a logo is enabled, instead of reserving the footer for the logo.
- Admin Product Post regeneration uses the same top-left placement.

## 3. Brand Profile preview matches real Product Posts
- The generated-content example now places the customer's logo at the same relative top-left position and scale as the real Product Post overlay.
- If the logo is disabled or removed, the example post shows **no overlay logo**.
- The previous business-name/example-logo fallback in the post image is removed.

## 4. Home → Innehållsplaner responsive rebuild
Desktop styling above 1450 px is left essentially intact because it already works well.

### 901–1450 px
- Explicit grid areas for icon, copy and action prevent older generic CSS from squeezing the copy column.
- Descriptions keep normal readable line widths.
- At narrower tablet widths, the action moves below the copy rather than stealing horizontal space.
- The three plan types stay inside one parent panel with flat separators instead of nested cards.

### <= 900 px
- One coherent Innehållsplaner card.
- Each plan type is a flat section, not a card-inside-card.
- Icon and copy align predictably.
- Actions become full-width under the copy.
- Summary facts become readable label/value rows.
- Planned-item metadata uses a clean responsive 2-column layout and drops to one column on small phones.
- Expanded details remain attached to their section and grow naturally.

### <= 620 px
- Metadata becomes single-column.
- Buttons remain tap-friendly.
- Body/detail text remains readable rather than collapsing to old 9–10 px dashboard text.
