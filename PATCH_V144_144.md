# PATCH V144.144 — Correct editorial layering, two-line copy and current logo default

## What was actually wrong
Transparent Product posts were still built as background+typography first and the exact transparent product was composited on top afterwards. That architecture meant any overlap could make the product physically cover the text. Prompt wording alone could not guarantee the correct layer order.

The extra lowest line also came from the optional supporting-copy role, and older automation rows could still carry `include_logo=false` from before a logo was added to the brand profile.

## Fix
### Transparent Product post architecture
The transparent path is now built in this order:

1. GPT-image-2 creates a **text-free background only**.
2. Spreelo composites the **exact original transparent product**.
3. GPT-image-2 creates a **transparent typography-only artwork** after seeing the finished background+product reference.
4. Spreelo crops/resizes that typography artwork into a deterministic centered lower safe zone and composites it **last**.
5. Brand logo overlay is applied afterwards when enabled in the current brand profile.

This makes the actual layer order:

**background → exact product → typography → logo**

The typography cannot end up physically underneath the product anymore. If it visually overlaps slightly, it is a final foreground layer rather than being hidden behind the product.

### Copy simplification
Product posts now use exactly two visible copy roles:

- headline
- exact product/model name

The optional supporting sentence / third copy line is removed.

### Typography positioning
For transparent Product posts the typography artwork is cropped from its alpha bounds, resized as one unit and then centered mathematically on the 1024px-wide canvas in the lower safe area. This prevents the image model from inventing a shifted text box.

### Logo behavior
Editorial Product posts now follow the **current brand-profile logo default**. A stale `include_logo=false` value on an older automation no longer suppresses a logo that has since been added and enabled in the brand profile.

The existing `logo_storage_path` public-URL fallback from V144.142 remains.
