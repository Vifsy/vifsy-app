# PATCH V144.143 — Editorial product post frame/placeholder removal

## Problem
The latest transparent-product safety update solved the text-overlap issue, but it reintroduced a new regression:

- GPT-image-2 was told too explicitly about a locked product box / reserved area
- in some posts the model visualized that instruction as a visible dashed frame or placeholder around the product area

This is not acceptable. The product area must stay visually clean while the typography still avoids the product.

## Fix
Updated the transparent editorial product-post prompt so it no longer exposes a literal placement box to the image model.

The generator now:

- keeps the future product in a centered upper/middle hero position
- tells the model to leave that area visually open instead of describing a drawable reserved box
- keeps all typography clearly below the future product area
- preserves a visible gap between the product and the first text line
- explicitly forbids placeholder outlines, frames, guides, bounding boxes and other visible markers

Also replaced the old “hard no-text zone” wording with softer composition language so the model focuses on clean layout rather than drawing a zone.

## Files changed
- `app/api/cron/run-automations/route.js`

## Effect
- The dashed frame / placeholder around the product area should no longer appear.
- Transparent-product editorial posts should still avoid text-overlap with the product.
- Text centering, footer breathing room and logo fallback behavior from V144.142 remain intact.
