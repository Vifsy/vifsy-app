# Spreelo v144.110 — Admin polish, resolved rescue cleanup and product typography

Built on **v144.109 Rescue Center + Annual Calendar + Static Email Translations**.

## 1. Resolved rescue failures leave `Misslyckat`

A successful admin regeneration now closes the failed occurrence in every relevant layer:

- the occurrence receives `metadata.admin_rescue_resolved_at`;
- the durable `admin_generation_work_items` row moves to `approval` and clears failure fields;
- older rescue flows that do not send `work_item_id` are repaired by matching `occurrence_id`;
- the Failed API defensively hides old repaired occurrences carrying `admin_regenerated_at` or `admin_rescue_resolved_at`;
- consumed rescue rows (`rescue_status = used`) do not remain in the Failed list or its badge count.

The failed automatic attempt is still preserved in database history/audit data; it simply stops being an actionable admin failure after a successful repair.

## 2. Product typography upgrade for static product posts and carousels

The shared static product renderer now follows the same transparent GPT Image typography approach proven in the AI-video flow:

- GPT Image receives the **finished product composition** as art-direction/placement reference;
- it may also receive the **verified original product image** as a second identity reference;
- the model returns **typography only on a transparent RGBA canvas**;
- the real product image remains untouched underneath;
- the output contract still rejects overly opaque/non-transparent generations and falls back safely if the typography asset cannot be used.

This shared renderer is used by the ordinary single-product image path and carousel product slides, so the improvement applies across the existing product formats that use this overlay system.

### Breadcrumb / path guard

Visible product overlay text now rejects navigation/path-like strings, including patterns such as:

`Hem > Godis > Gelé > Colanappar`

It also excludes URLs, slugs and multi-level storefront paths from the generated typography prompt.

## 3. Clear social-channel prerequisite on plan activation

If no social channel is connected:

- the activation card shows a visible warning before the customer clicks Activate;
- clicking the activation CTA opens the existing proper social-channel modal instead of relying on the tiny inline message;
- the modal links directly to Social channels;
- the generic modal text now explains that a valid publishing destination is required before scheduling.

The desktop activation CTA is also narrower, centered and taller (`max 520px`, `56px` minimum height), while remaining full width on mobile.

## 4. Compact admin tabs with notification badges

The Admin post workbench tabs are redesigned as compact app-icon controls:

- Kommande
- Godkännande
- Misslyckat
- Historik

Pending counts appear as a small notification badge on the corresponding icon. Counts are loaded from the global durable admin work queue, so they represent all customer work visible to admin, not only the currently selected brand.

## 5. Safe cleanup of the current admin test account

Admin Post Approvals now includes **Rensa mina testinlägg**.

For safety it:

- requires the exact confirmation `RADERA MIN TESTDATA`;
- affects **only the currently authenticated admin user's own generation data**;
- never deletes customer accounts or brand profiles;
- stops that admin user's current automation rules first so cron does not immediately recreate Upcoming work;
- releases reserved credits through the existing credit-release RPC when applicable;
- clears the current admin user's work items, review cases, notifications, run logs, occurrences and posts;
- post-linked generation-cost summaries/events are removed automatically by the existing database cascade when posts are deleted;
- admin queue statistics are reloaded from the underlying tables after cleanup.

This is intentionally not a global customer-data cleanup button.
