# Spreelo v144.109 — Rescue Center + Annual Calendar Renewal + Static Email Translations

Base: **v144.108 Fail Fast + Remote Rescue Images**.

## What this release adds

### 1. Admin Rescue Center

A new **Admin → Rescue Center** collects three rescue areas in one place:

- failed website/brand analyses,
- failed product-post rescue handoff (links into the existing v144.108 post rescue flow),
- annual campaign-calendar renewals that require manual help.

The Rescue Center supports export of a structured ChatGPT rescue brief, import of a returned ZIP/JSON package, preview, approval and status tracking.

### 2. Brand-analysis rescue

When a website analysis is blocked or otherwise reaches a rescue-worthy terminal failure, Spreelo can create an `admin_rescue_cases` item instead of leaving the brand in an unclear failed state.

A successful approved analysis rescue writes back through Spreelo's normal brand-profile/campaign-opportunity persistence path so the brand continues in the ordinary product after the one-time rescue.

Brands rescued manually can be marked with `calendar_generation_mode = manual_rescue` so future annual renewals do not repeatedly waste work on an inaccessible source.

### 3. Annual campaign-calendar renewal

A new daily maintenance cron prepares annual campaign calendars:

- **December 1 onward:** prepares the next calendar year.
- **January–November:** continues finishing the current calendar year for any brands left behind at New Year.

Accessible brands enter the existing durable brand-analysis job system with `analysis_kind = annual_calendar_refresh` and `target_calendar_year`.

Brands configured for manual rescue are placed directly in the annual rescue queue. Automatic annual refreshes that fail can also fall back into that queue.

### 4. Calendar-complete email

When a new annual calendar is actually completed/activated, Spreelo sends the customer a polished service email informing them that the new calendar is ready.

The email ledger uses a brand/year entity key, so the same annual calendar notification is not intentionally sent twice. Failed deliveries can be retried from the maintenance flow/Admin Rescue Center.

### 5. No send-time AI translation for standard emails

The `emails` namespace now returns from a static/file-backed translation branch **before** the OpenAI missing-label translation path.

This applies to standard transactional/service email copy including:

- plan/campaign activation email,
- welcome email,
- analysis-complete email,
- annual calendar-updated email.

Existing persisted email translation packs may still be reused as a compatibility layer, but sending an email no longer creates a new OpenAI translation request. Missing static/persisted strings fall back safely to English.

### 6. Existing v144.108 product rescue preserved

The product-post rescue path remains intact, including verified direct HTTPS `image_url` support and copying the retrieved original image into Spreelo Storage before review/regeneration.

## Database

**New SQL migration required:**

`supabase/v144_109_rescue_center_annual_calendar_email.sql`

It adds:

- calendar generation/rescue state to `brand_profiles`,
- annual analysis fields to `brand_analysis_jobs`,
- `brand_calendar_renewals`,
- `admin_rescue_cases`,
- `calendar_updated` to the lifecycle-email type constraint.

## Cron

Adds:

`/api/cron/calendar-renewal-maintenance` → daily at `04:10 UTC`.

No new environment variables are required; the route uses the existing `CRON_SECRET`, Supabase service-role configuration and Resend configuration.
