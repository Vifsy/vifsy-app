# Spreelo v144.112 — Analysis Fail-Fast + Customer Rescue Handoff

Base: **v144.111 Rescue Credit Lifecycle + Localized Customer Email**.

Admin security/MFA is **not** included in this release. It is intentionally deferred to a later version.

## 1. Confirmed website security blocks stop immediately

When a normal brand/website analysis receives `WEBSITE_SECURITY_BLOCKED`:

- automatic analysis ends immediately;
- Spreelo does not start hosted OpenAI web-research fallback;
- no repeated blocked-site analysis attempts are scheduled;
- the analysis job moves to `manual_rescue_pending`;
- an Admin Rescue Center case is created immediately;
- the brand is marked `analysis_rescue_required = true`;
- the customer is released from the waiting screen.

This uses the Rescue Center introduced in v144.109 rather than paying for repeated research against a source Spreelo already knows it cannot read reliably.

## 2. Direct website timeout gets one short retry

`WEBSITE_FETCH_TIMEOUT` is treated differently from a confirmed security block:

- first timeout: one short automatic retry after approximately 15 seconds;
- second timeout: stop automatic analysis and hand the brand to Admin Rescue;
- no hosted web-research fallback is started.

This preserves a small amount of resilience for transient network problems without allowing a long or expensive retry chain.

## 3. Legacy web-research-waiting analysis jobs are converted to rescue

If an older queued analysis is already in `web_research_waiting` when v144.112 is deployed, the worker no longer continues that paid research path. It converts the job to the new manual-rescue handoff and creates/reuses the Admin Rescue Center case.

## 4. Customer popup in onboarding

The first brand setup now recognizes the manual-rescue state as an expected handoff instead of showing a generic error.

The customer receives a clear localized popup explaining:

- why automatic analysis stopped (security block or repeated timeout);
- that they do not need to do anything;
- that Spreelo will complete both the brand analysis and the personal campaign calendar;
- that the page does not need to remain open;
- that an email will be sent when everything is ready.

The primary action takes the customer into Spreelo instead of leaving them trapped on the onboarding loading screen.

## 5. Same handoff in Brand Profile

Brand Profile uses the same rescue contract:

- the analysis modal switches to a dedicated rescue-completion message;
- raw backend/security errors are not shown as the main customer explanation;
- after closing the modal, the Brand Profile shows a persistent **manual analysis pending** state;
- normal retry/edit CTAs are suppressed while `analysis_rescue_required` is true;
- reloading the page preserves the pending state by reading `analysis_rescue_required` and `website_access_status` from `brand_profiles`.

When admin approves the rescue package, the existing v144.109 flow clears `analysis_rescue_required`, saves the profile/calendar normally and sends the completion email.

## 6. Completion email wording

The existing `analysis_completed` lifecycle email now makes the complete result clearer:

**brand analysis + personal campaign calendar are ready**.

The underlying v144.111 locale policy is preserved: the user's saved app language remains authoritative for customer lifecycle email language. No new per-send translation design was added in this release.

## 7. No database migration

v144.112 reuses existing fields/tables from v144.109/v144.111:

- `brand_profiles.analysis_rescue_required`
- website access status fields
- `brand_analysis_jobs.user_message_code`
- `admin_rescue_cases`
- existing lifecycle email ledger

**No new Supabase SQL is required.**
