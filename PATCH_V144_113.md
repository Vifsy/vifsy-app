# Spreelo v144.113 — Analysis Rescue `next_attempt_at` Fix

Base: **v144.112 Analysis Fail-Fast + Customer Rescue Handoff**.

## Problem fixed

A confirmed website security block (for example an HTTP 403 from a protected site) correctly entered the v144.112 manual-rescue path, but that path attempted to write:

`next_attempt_at = null`

The durable brand-analysis schema defines `brand_analysis_jobs.next_attempt_at` as `NOT NULL`, so Supabase rejected the update before the Rescue Center case could be created.

## Change

The manual-rescue handoff no longer clears `next_attempt_at`.

The job is still written as:

- `status = failed`
- `step = manual_rescue_pending`
- `progress = 100`
- customer/manual-rescue message code saved
- worker lease released
- Admin Rescue Center case created
- brand marked as requiring manual analysis rescue

A failed job is not claimable by the durable queue, so retaining the existing non-null timestamp has no retry effect.

## Database

**No new SQL migration is required.**

## Regression protection

Added `test:v144.113`, which verifies that the schema requires a non-null `next_attempt_at` and that the manual-rescue handoff never writes a null value to it.
