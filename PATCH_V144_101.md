# Spreelo v144.101 — worker lane guard + immediate admin runtime alerts

Built directly on v144.100.

## 1. Hard generation concurrency guard

The existing shared queue, per-rule queue lock, one-occurrence claim, website-domain lock, fairness selection and batch size are unchanged.

A new expiring lease now protects each dedicated generation lane:

- worker-1 → max one active generation invocation
- worker-2 → max one active generation invocation
- worker-3 → max one active generation invocation
- worker-4 → max one active generation invocation
- worker-5 → max one active generation invocation

If the next minute's cron reaches a lane that is still generating, that invocation does **not** claim another generation job. It exits successfully with `worker_lane_busy: true`.

The lease defaults to 12 minutes and is released in a `finally` block. If Vercel kills/crashes the process, the database lease expires automatically. The lease is intentionally not extended indefinitely.

The guard is placed around the generation queue, after the existing scheduled-publishing sweep, so protecting long-running generation does not unnecessarily stop a due social post from being published.

## 2. No risky dependency on the new monitoring layer

Lease metadata updates, incident persistence and incident email delivery are non-fatal. A monitoring/logging problem does not fail an otherwise valid generation.

If the v144.101 SQL migration has not yet been applied, the code preserves the previous queue behavior rather than taking customer automation offline. For the hard lane guard to be active, run the SQL before deploying the app code.

## 3. Immediate detailed admin email alerts

The existing Resend admin failure notification has been expanded into a detailed runtime alert.

Critical alerts now cover, among other things:

- terminal post-generation failures
- failures before an occurrence could be claimed
- terminal social publishing failures
- top-level worker/cron crashes
- stale runs that exceeded the runtime safety window

Warnings are also sent earlier for:

- repeated website rate limiting (from retry 2)
- repeated transient runtime failures (from retry 2)
- a worker lane that remains active unusually long (default 8 minutes)

A normal busy worker for a few minutes does not send an email.

## 4. Diagnostic information in the email

Where available, the admin email includes:

- incident ID and severity
- customer/brand name and website
- user ID and brand profile ID
- campaign/plan name
- content type and content format
- scheduled date/time
- worker lane
- exact failure stage and failure code
- automation rule ID
- occurrence ID
- post ID
- automation run-log ID
- queue attempt/retry count
- run duration
- provider/model information from the existing cost ledger
- exact provider cost recorded so far
- queue snapshot
- products involved and source URLs
- recent jobs handled by the same worker invocation
- technical error message and stack when available

API keys, access tokens and provider secrets are not deliberately included in the email.

## 5. Anti-spam / durable incident history

New `admin_runtime_incidents` storage groups repeated identical incidents. The first incident sends immediately. Repeated matching incidents are grouped and email is rate-limited (default 10 minutes), so a provider outage cannot flood the admin inbox.

If Resend itself fails, the email reservation is cleared so a later event can retry the notification rather than being incorrectly suppressed.

## Database migration — REQUIRED before deploy for the hard guard

Run:

`supabase/v144_101_worker_lane_leases_runtime_incidents.sql`

The migration is idempotent and creates:

- `automation_worker_leases`
- `acquire_automation_worker_lane(...)`
- `release_automation_worker_lane(...)`
- `admin_runtime_incidents`
- `record_admin_runtime_incident(...)`

The new tables are not exposed to anon/authenticated users; they are service-role/admin runtime data.

## Existing environment variables

No new mandatory environment variable is required. Alert delivery continues to use the existing `RESEND_API_KEY` and configured Spreelo admin email(s).

Optional tuning variables:

- `AUTOMATION_WORKER_LANE_LEASE_SECONDS` (default 720)
- `AUTOMATION_WORKER_LONG_RUNNING_ALERT_SECONDS` (default 480)
- `ADMIN_INCIDENT_EMAIL_COOLDOWN_SECONDS` (default 600)
